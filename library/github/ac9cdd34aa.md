## Why I kept it

On-device model runtime for a demo that should not send the notes to a cloud model.

## What it is

GenieX allows running large language models and vision language models locally on Qualcomm devices without sending notes to a cloud model. The framework supports NPU, GPU, and CPU for efficient on-device AI processing.

## Use it for

When the user needs to run a demo without cloud integration or data transmission.

GenieX is an **on-device Gen AI inference runtime for Qualcomm devices**. Bring almost any GGUF model from Hugging Face, ModelScope, or Docker Hub, or use a pre-compiled bundle from [Qualcomm AI Hub](https://aihub.qualcomm.com/models/). Run it locally on the **Hexagon NPU, Adreno GPU, or CPU** in a few lines of code. One C SDK underneath is exposed through a CLI, Python, Kotlin/Java, Docker, and an OpenAI-compatible server. It is the community version of Qualcomm GENIE.

[![GenieX architecture: CLI, Python, Java, Docker, and OpenAI-compatible Serve interfaces sit on a single GenieX SDK, which dispatches to the llama.cpp runtime (GGML over CPU / GPU / Hexagon HTP kernels) or the Qualcomm AI Engine Direct runtime on the NPU — across Windows, Android, and Linux.](https://github.com/qualcomm/GenieX/raw/main/docs/Mintlify-image/geniex_arch_v2.png)](https://github.com/qualcomm/GenieX/blob/main/docs/Mintlify-image/geniex_arch_v2.png)

**Install**

- **Windows ARM64** — [download the installer](https://github.com/qualcomm/GenieX/releases), run it, then open a new terminal.
- **Linux ARM64** — one line, no `sudo`:

```
curl -fsSL https://qaihub-public-assets.s3.us-west-2.amazonaws.com/qai-hub-geniex/install.sh | sh
```

**Run** — chat with any model in one line (drag in an image for VLMs):

```
# GGUF from Hugging Face → llama.cpp (NPU / GPU / CPU)
geniex infer google/gemma-4-E4B-it-qat-q4_0-gguf

# GGUF from ModelScope → llama.cpp (NPU / GPU / CPU)
geniex infer https://modelscope.cn/model
